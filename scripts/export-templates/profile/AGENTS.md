# AGENTS.md

This repository or directory started as an exported Productive K3S profile
bootstrap bundle. It can be used as-is to replay the exported infrastructure
installation, or as the initial codebase for a project-specific infrastructure
bootstrap repository.

## Project Origin

- Generated by: `productive-k3s-infra profile export`
- Subject: `{{subject_ref}}`
- Packaged artifact: `{{artifact_name}}`
- Runtime entrypoint: `./productive-k3s-infra.sh`

The bundle vendors the Productive K3S Infra runtime files needed to replay the
profile installation. It should not need to download a separate Infra bundle
before starting.

This code is intentionally ordinary shell and packaged YAML/TGZ content. A
downstream project may adapt it, wrap it, replace the packaged profile, or fork
the vendored runtime. Prefer preserving the notes below so future maintainers and
agents can still identify what came from Productive K3S and what became local
project code.

## Code Map

- `install.sh`: top-level installation entrypoint for this exported bundle.
  It loads `install-config.env`, runs `preflight.sh` by default, and then
  delegates to the bundled Infra runtime.
- `preflight.sh`: validates the local bundle shape, packaged profile metadata,
  and local prerequisites for the declared profile engine.
- `install-config.env`: generated configuration defaults captured when the
  bundle was exported. This is the preferred file for environment-level changes.
- `override.env`: optional local override file included when the export was
  created from a source profile or with explicit overrides.
- `manifest.json`: generated metadata describing the exported subject and
  command. Treat it as audit data.
- `{{artifact_name}}`: packaged profile artifact consumed by Infra. It contains
  `profile.yaml`, profile defaults, and the scenario code required by the
  package contract.
- `productive-k3s-infra.sh`: public Infra runtime entrypoint vendored into this
  bootstrap.
- `scripts/`: vendored Infra runtime internals. The most relevant paths are
  `scripts/productive-k3s-infra.sh` for command dispatch and packaged profile
  execution, and `scripts/release-config.sh` for runtime release metadata.

## How To Operate

- Run `./preflight.sh` before installation to verify the bundle structure,
  profile package metadata, and host prerequisites for the declared engine.
- Run `./install.sh` to execute the profile installation.
- Use `./install.sh --skip-preflight` only after preflight was already run in
  the same target environment.
- Use `./install.sh --preflight-only` when an automation agent should validate
  the bundle without installing infrastructure.

## Editing Guidance

- Treat files under `scripts/` and `productive-k3s-infra.sh` as vendored
  Productive K3S runtime code until the project intentionally forks them.
- Prefer changing `install-config.env`, `override.env`, or passing runtime
  flags to `install.sh` over editing vendored runtime scripts.
- If this bootstrap becomes the starting point for a forked deployment project,
  keep local project logic outside the vendored runtime where possible. Add
  wrapper scripts, provider env files, documentation, or CI around `install.sh`
  instead of patching Infra internals.
- If the packaged profile itself must change, rebuild or replace
  `{{artifact_name}}` from the source profile repository and keep the updated
  artifact next to this file.
- Keep `manifest.json`, `{{artifact_name}}`, `README.md`, and this file
  together if this bootstrap bundle is copied into another repository.
- Do not assume this bundle contains provider credentials. Cloud and remote
  profile installs still need their provider-specific environment, SSH material,
  and network access at runtime.

## Suggested Agent Workflow

1. Read `README.md`, this file, `manifest.json`, and `install-config.env`
   before editing.
2. Inspect `{{artifact_name}}` with `tar -tzf {{artifact_name}}` to understand
   the packaged profile, defaults, and scenario code.
3. Review `override.env` if present; it is usually where environment-specific
   values from source-profile exports are captured.
4. Run `./preflight.sh` after any change to configuration or packaged
   artifacts.
5. Add local automation around `install.sh` for project-specific behavior.
6. If changing vendored runtime files, treat that as a fork of Productive K3S
   Infra and document the divergence in this repository.

## Implementation Scope

This bootstrap installs an already-packaged profile. It does not own catalog
lookup, profile source curation, or application stack installation beyond what
the packaged profile scenario invokes. Those responsibilities live above or
beside Infra in the Productive K3S ecosystem. A future agent should preserve
that boundary unless the project intentionally forks the vendored runtime.
